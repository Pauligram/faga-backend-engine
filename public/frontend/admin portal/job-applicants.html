Production Integration Notes
Backend endpoints and security requirements for applicant management.

Recommended API endpoints

  • GET /api/admin/jobs/applicants
  • GET /api/admin/jobs/applicants/:applicantId
  • GET /api/admin/jobs/applicants/:applicantId/cv
  • PATCH /api/admin/jobs/applicants/:applicantId
  • POST /api/admin/jobs/applicants/:applicantId/message
  • POST /api/admin/jobs/applicants/:applicantId/extend-access
  • POST /api/admin/jobs/applicants/:applicantId/suspend
  • GET /api/admin/jobs/applicants/:applicantId/applications
  • GET /api/admin/jobs/applicants/export

Security requirements

  • Enforce administrator authentication and RBAC server-side.
  • Applicant ownership and permissions must never be determined by browser data.
  • CVs must be stored privately and served through short-lived authorized URLs.
  • Do not expose passwords, payment credentials, access tokens or provider secrets.
  • Audit applicant profile changes, CV access, messages, suspension and access extensions.
  • Use server-side pagination, filtering and sorting.
  • Protect applicant PII and restrict staff access according to role.
  • Verify payment and access entitlement against authoritative backend records.
  • Do not allow administrators to alter historical payment records merely by editing applicant data.
  • Apply document type, file size and malware/security validation to uploaded CVs.
